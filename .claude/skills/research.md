# /research スキル — AIリサーチワークフロー

## 概要
粗いテーマ入力から、ChatGPT Deep Research投げ込み用の精密な論点設計書を生成し、Notionに保存するエンドツーエンドのリサーチワークフロー。

## 起動方法
```
/research [テーマや背景を自由に記述]
```

---

## ワークフロー

### Phase 0: 入力受付
ユーザーから粗いテーマ・背景・目的を受け取る。
何も書かれていない場合は「どのようなテーマについてリサーチしますか？」と聞く。

---

### Phase 1: 論点ヒアリング（対話型）

以下の観点から**3〜5問**を選んでヒアリングする。
一度に全問を出さず、会話の流れに応じて追加質問を行う。

**ヒアリング観点**：
1. **目的・用途**：この調査を何のためにするか（意思決定、提案資料、社内共有など）
2. **意思決定者**：誰に向けた調査か（経営層、外部パートナー、自社チームなど）
3. **時間軸**：短期（今月中に結論）か中長期（3〜6ヶ月の検討材料）か
4. **スコープ**：地域（国内/海外）、産業、技術領域、対象規模など
5. **制約・前提**：すでに決まっていること、外せない条件
6. **仮説の有無**：すでに「こうではないか」と思っていることはあるか
7. **競合・類似事例の知識**：すでに知っている事例・プレイヤーはあるか

ヒアリングが完了したら「論点整理に入ります」と宣言して次フェーズへ。

---

### Phase 2: 論点マップ + 仮説構造化

`hypothesis-builder` エージェントを使用して以下を生成する。

#### 論点マップ（Issue Map）
```
【大論点】リサーチの中心問い（1つ）
  ├─ 【中論点1】サブ問い
  │    ├─ 【小論点1-1】具体的な問い
  │    └─ 【小論点1-2】具体的な問い
  ├─ 【中論点2】...
  └─ 【中論点3】...
```

#### 仮説リスト
各中論点に対して「現時点での仮説（答えの候補）」を明示する。
仮説は「〜と考えられる。なぜなら〜だから。」の形式で記述。
確度（高/中/低）も付与する。

ユーザーに論点マップと仮説リストを提示し、修正・追加の確認を取る。
承認されたら次フェーズへ。

---

### Phase 3: 初期デスクリサーチ

`desk-researcher` エージェントを使用して初期調査を実施する。

**調査方針**：
- 公式機関・一次情報・信頼度の高い情報源を優先（省庁、研究機関、業界団体、上場企業IR等）
- 各論点につき2〜3件の確度の高いソースを収集
- 情報の新しさを確認（原則1〜3年以内を優先）

**収集する情報**：
1. 各仮説を支持または否定する事実・データ
2. 主要プレイヤー・競合サービスの概要
3. 規制・制度・補助金など制約条件
4. 市場規模・成長率・トレンドデータ（数値情報）

調査結果を簡潔にまとめてユーザーに提示し、
「この結果をもとにDeepResearch設計書を作成します」と確認を取る。

---

### Phase 4: DeepResearch設計書の生成

`templates/deep-research-brief.md` テンプレートを使用して、
ChatGPT Deep Researchに直接投げ込める精密な設計書を生成する。

設計書の要件：
- 曖昧な指示を含まない（具体的な問いと検証条件を明記）
- 優先情報源の種類を指定する（省庁資料、学術論文、IRなど）
- 各論点の「何を裏付けたいか」を明示する
- 期待するアウトプット形式を指定する

設計書を出力し、ユーザーに確認を取る。

---

### Phase 5: Notion出力

`notion-writer` エージェントを使用して以下をNotionに保存する。

1. **Source DB**: 初期リサーチで収集したソース情報
2. **リサーチドキュメント**: 論点マップ + 仮説 + DeepResearch設計書

保存完了後、NotionのURLを返す。

---

## 出力形式の基準

- **論点マップ**：ツリー構造で視認性を確保
- **仮説リスト**：表形式（仮説 / 根拠 / 確度）
- **DeepResearch設計書**：コピペ可能なプロンプト形式
- **Notionドキュメント**：スライド化を意識した見出し構造

---

## 注意事項

- ヒアリング中は1度に多く聞きすぎない（最大3問/回）
- 仮説は「ユーザーの仮説」を引き出すことを優先し、Claudeの推測を押し付けない
- 情報源は必ずURLと取得日を記録する
- 論点が発散した場合は「今回のスコープ外」として整理する
